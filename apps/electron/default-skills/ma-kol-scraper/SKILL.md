# 蒲公英 KOL 采集脚本生成器

## 核心职责

根据用户的产品定位和筛选需求，端到端完成：**探索参数 → 生成脚本 → 运行采集 → 输出 CSV → 校验质量**。

## 何时使用

**✅ 合适**
- 用户需要从蒲公英批量采集/导出达人数据
- 用户有产品/品牌，需要按条件筛选 KOL
- 需要定制化采集脚本（城市/粉丝量/报价等）

**❌ 不合适**
- 只需单个 KOL 详情 → 用 `ma-kol-crm`
- 需要投放策略而非数据 → 用 `ma-kol-pyramid`
- 无 Chrome 或蒲公英未登录

## 前置条件

- Chrome 已开启远程调试：`--remote-debugging-port=9222`
- 已在 Chrome 中登录蒲公英（pgy.xiaohongshu.com）
- Python 已安装：`pip install playwright`

## 核心工作流

### Step 1 · CDP 连接 Chrome

通过 Playwright CDP 连接用户正在使用的 Chrome。**关键规则**：
1. 使用 `connect_over_cdp("http://127.0.0.1:9222")`
2. 从已有页面中找蒲公英页面（`pgy.xiaohongshu.com`），没有则导航到 `https://pgy.xiaohongshu.com/solar/pre-trade/note/kol`
3. **不要启动新浏览器实例**
4. 连接失败时告知用户检查远程调试端口

### Step 2 · 全参数探索

**不要问用户要参数。** 先提取页面上所有可用筛选选项，再让用户从中选择。

1. 用 `page.evaluate()` 提取 DOM 中的筛选选项（多策略兜底：`.common-filters-wrapper` / `.d-select` / `.d-tabs` / `.d-tag-group`）
2. 截取蒲公英页面完整截图保存到工作区文件目录
3. 以结构化方式展示给用户（类目/地域/粉丝量/报价/内容标签/粉丝画像等）
4. 分批次引导用户选择：
   - 第一批：产品名 + 博主类目 + 性别 + 地域
   - 第二批：粉丝量 + 报价 + 内容标签
   - 第三批：粉丝地域/年龄/其他（非必选）
5. 若用户一次性提供了完整需求，直接解析、与可用选项交叉验证后确认

### Step 3 · 生成采集脚本

基于 `scripts/scraper_template.py` 的结构，根据用户参数完全定制：

1. **配置区**：将所有用户参数转为 `cfg` 字典（含 `workspace_dir` / `output_file`）
2. **搜索区**：用 `references/payload.md` 的完整 payload 结构，只替换筛选条件
3. **采集区**：实现**两阶段采集**模式：

```
预筛（列表页，地域/报价/粉丝/标签）
  ↓ 通过
阶段一：fetch_kol_detail() → 采集 blogger + fans_profile + notes_rate + notes_detail 首页
  ↓
轻量检查（按顺序）：
  ① 详情页二次过滤（地域/报价/粉丝/标签）
  ② 活跃度检查（近 N 天有更新）
  ③ 水号检测（阅读/点赞比 11.43~30.0）
  ④ 粉丝城市检查（前五城市含目标城市）
  ↓ 全部通过
阶段二：extract_coop_notes() → 重新导航详情页，直跳笔记案例→合作笔记，翻页+抽屉提取
  ↓
构建行 → CSV 输出
```

4. **关键策略**：
   - 详情页用临时标签页 + `page.on("response")` 捕获 API
   - 每个 KOL 采集完关闭标签页
   - 阶段一/二各自外层重试 2 次
   - 失败不中断整体流程
   - **每收集到 10 个匹配 KOL 写入一次 CSV**，防止长时间采集中断丢数据

**脚本写入路径**：`{WORKSPACE_FILES}/scrape_{product}_{cities}.py`

### Step 4 · 运行 + 展示

1. 用 `python3 {script_path}` 运行，实时输出进度
2. 运行完成后：展示 CSV 路径、KOL 总数、前几行摘要、脚本路径

### Step 5 · 数据质量校验

运行后**必须**对 CSV 做完整性校验。校验分为**硬性条件**和**软性提醒**两类：

**🔴 硬性条件（需要修复或确认的信息缺失）：**
1. 有合作笔记篇数但最低曝光缺失（抽屉提取失败 → 需考虑手动复核或重新采集）
2. CPM 异常高（最低曝光提取错误 → 需排查是否提取到了错误字段）
3. 阅读量 > 曝光量（数据矛盾 → 需排查数据采集异常）
4. 报价为空 / 粉丝量为 0（数据缺失 → 需排查是否采集异常）

**🟡 软性提醒（根据 campaign 和产品的具体要求来判断，非硬性条件）：**
5. 女性粉丝占比异常低（若目标用户为女性则需注意，但非必须修正的数据错误）

输出校验报告给用户（🔴 硬性问题 / 🟡 需确认 / ✅ 数据完整），给出修复建议及需人工判断的说明。

## 采集字段清单

CSV 输出包含以下字段。**生成采集脚本时，必须使用「仅自然流量」（`advertiseSwitch=0`）获取日常笔记和合作笔记的 notes_rate 数据，不能使用默认的「全部流量」。时间范围筛选近 30 天。**

| 类别 | 字段 | 数据来源 |
|------|------|---------|
| **基础信息** | 达人名称、内容类目、地域、粉丝量、粉丝所在区域（前五城市）、获赞与收藏 | blogger API |
| **粉丝画像** | 女性粉丝占比 | fans_profile API |
| **报价** | 图文报价（万）、视频报价（万） | blogger API（元→万转换） |
| **日常笔记**（近30天·仅自然流量） | 发布篇数、曝光中位数、阅读中位数、点赞中位数 | notes_rate API **必须传 `advertiseSwitch=0`** |
| **合作笔记**（近30天·仅自然流量） | 发布篇数、曝光中位数、阅读中位数、点赞中位数 | notes_rate API **必须传 `advertiseSwitch=0`** |
| **合作笔记最低曝光**（近30天） | 最低曝光、最低曝光阅读、最低曝光点赞、最低曝光收藏、最低曝光评论、最低曝光时间、最低曝光品牌 | notes_detail API + 抽屉 DOM 提取 |
| **合作笔记最低点赞**（近30天） | 最低点赞、最低点赞阅读、最低点赞收藏、最低点赞评论、最低点赞时间、最低点赞品牌 | notes_detail API + 抽屉 DOM 提取 |
| **预估指标** | 预估CPM、预估CPE | 根据最低曝光/最低点赞计算 |

## 关键原则

1. **CDP 始终使用已打开的 Chrome**
2. **先探索再提问** — 不要跳过 Step 2
3. **搜索 API payload 必须完整** — 不要省略字段
4. **详情页必须关闭** — 每处理完一个 KOL 就关闭
5. **CSV 去重** — 多次运行不重复
6. **脚本可复用** — 为用户加 `--config` 参数支持下次复用
7. **所有产出在工作区文件目录**
8. **平台专注** — 仅小红书蒲公英
