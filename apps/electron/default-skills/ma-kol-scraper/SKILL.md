# 蒲公英 KOL 采集脚本生成器

## 核心职责

根据用户的产品定位和筛选需求，端到端完成：**探索参数 → 生成脚本 → 运行采集 → 输出 CSV → 校验质量**。

## 何时使用

**✅ 合适**
- 用户需要从蒲公英批量采集/导出达人数据
- 用户有产品/品牌，需要按条件筛选 KOL
- 需要定制化采集脚本（城市/粉丝量/报价等）

**❌ 不合适**
- 只需单个 KOL 详情 → 用 `ma-kol-crm`
- 需要投放策略而非数据 → 用 `ma-kol-pyramid`
- 无 Chrome 或蒲公英未登录

## 前置条件

- Chrome 已开启远程调试：`--remote-debugging-port=9222`
- 已在 Chrome 中登录蒲公英（pgy.xiaohongshu.com）
- Python 已安装：`pip install playwright`

## 核心工作流

### Step 1 · CDP 连接 Chrome

通过 Playwright CDP 连接用户正在使用的 Chrome。**关键规则**：
1. 使用 `connect_over_cdp("http://127.0.0.1:9222")`
2. 从已有页面中找蒲公英页面（`pgy.xiaohongshu.com`），没有则导航到 `https://pgy.xiaohongshu.com/solar/pre-trade/note/kol`
3. **不要启动新浏览器实例**
4. 连接失败时告知用户检查远程调试端口

### Step 2 · 全参数探索

**不要问用户要参数。** 先提取页面上所有可用筛选选项，再让用户从中选择。

**参数提取策略（多策略兜底，应对不同版本的蒲公英页面）：**

| 策略 | 目标元素 | 说明 |
|------|---------|------|
| A：筛选栏 | `.common-filters-wrapper`, `.note-filters-wrapper`, `.filter-bar` | 所有可视化的筛选标签和下拉 |
| B：下拉框 | `.d-select`, `.ant-select`, `.el-select` | 点击展开后取子选项 |
| C：Tab 栏 | `.d-tabs`, `.ant-tabs`, `.el-tabs` | Tab 标题文本 |
| D：标签组 | `.d-tag-group`, `.filter-tags`, `.tag-list` | 可选标签及其选中状态 |

提取逻辑：遍历所有目标元素 → 读取 `textContent` → 去重 → 结构化整理为类目/地域/标签等分组。必须使用 `page.evaluate()` 在浏览器 JS 环境中执行 DOM 查询，而非 Python 端解析。

**截图保存：** 截取蒲公英页面完整截图到工作区文件目录，告知用户确认页面加载正常。

**向用户展示可用选项：** 将提取结果以结构化方式展示（类目/地域/粉丝量/报价/内容标签/粉丝画像等），截图一并展示。

**分批次引导用户选择：**
- **第一批（核心）：** 产品/品牌名称、博主类目（单选）、性别、地域（多选）
- **第二批（量化）：** 粉丝量范围、合作报价范围、内容标签（多选）
- **第三批（高级，非必选）：** 粉丝地域、粉丝年龄/性别、内容关键词、其他特殊筛选

如果用户一次性提供了完整需求，直接解析并交叉验证后向用户确认，无需逐条提问。

### Step 3 · 生成采集脚本

基于 `scripts/scraper_template.py` 的结构，根据用户参数完全定制：

1. **配置区**：将所有用户参数转为 `cfg` 字典（含 `workspace_dir` / `output_file`）
2. **搜索区**：用 `references/payload.md` 的完整 payload 结构，只替换筛选条件
3. **采集区**：实现**两阶段采集**模式。每个 KOL 打开一个临时标签页（`context.new_page()`），通过 `page.on("response")` 监听器按 URL 模式捕获 API 数据（blogger / fans_profile / notes_rate / notes_detail），采集完关闭标签页。

**阶段一（采集基础信息，`fetch_kol_detail`）：**
导航至 `blogger-detail/{user_id}` → 等待 blogger API 响应 → 关闭弹窗（`.d-modal-close`）→ 点击「数据概览」tab 并 scroll 到数据表现区域 → 切换流量类型为「仅自然流量」（点下拉选单中的"仅自然流量"）→ 依次点击「日常笔记」/「合作笔记」按钮触发 notes_rate → 点击「笔记案例」tab → 筛选「合作笔记」segment → 得到 blogger + fans_profile + notes_rate + notes_detail 首页数据。

**阶段一之后的轻量检查（按顺序）：**
① 详情页二次过滤（地域/报价/粉丝/标签）→ ② 活跃度检查（近 10 天有更新，通过 `is_active_recently` 判断 daily notes_rate 的发布篇数）→ ③ 水号检测（阅读/点赞比 11.43~30.0，通过 `is_water_account` 判断）→ ④ 粉丝城市检查（前五城市含目标城市）。**任何一项不通过 → continue 跳过，不执行阶段二。**

**阶段二（翻页 + 抽屉提取，`extract_coop_notes` 独立方法）：**
只在前置检查全部通过后调用。导航到详情页 → 直接跳转「笔记案例 → 合作笔记」→ 翻页循环（`pageNum=1` 开始，最大 N 页）→ 逐页点击页脚页码按钮（`.d-pagination-page`）→ 过滤超过 `coop_note_months` 个月的合作笔记 → 逐条点击卡片（`.note-card-wrapper`）打开抽屉 → 从 `.d-drawer-content` 的 `innerText` 中解析曝光量、阅读量、点赞量等 → 关闭抽屉（`Escape` 键兜底 `.d-drawer-guard`）。

**流程概览：**

4. **关键策略**：
   - 详情页用临时标签页 + `page.on("response")` 捕获 API
   - 每个 KOL 采集完关闭标签页
   - 阶段一/二各自外层重试 2 次
   - 失败不中断整体流程
   - **每收集到一个匹配 KOL 就写入 CSV**，防止长时间采集中断丢数据

**脚本写入路径**：`{WORKSPACE_FILES}/scrape_{product}_{cities}.py`

### Step 4 · 运行 + 展示

1. 用 `python3 {script_path}` 运行，实时输出进度
2. 运行完成后：展示 CSV 路径、KOL 总数、前几行摘要、脚本路径

### Step 5 · 数据质量校验

运行后**必须**对 CSV 做完整性校验。校验分为**硬性条件**和**软性提醒**两类。对每一条达人数据逐行检查：

**🔴 硬性条件（需要修复或确认的信息缺失）：**
1. **合作笔记篇数 > 0 但最低曝光缺失** → 抽屉提取失败，需复核是否点击/解析出错，或手动复核该达人
2. **CPM 异常高（如 > 10000）** → 最低曝光提取到了错误极小值，导致计算失真，需排查 `note_exposure` 解析逻辑
3. **阅读量 > 曝光量数据矛盾** → 正常情况阅读 ≤ 曝光，若不满足说明数据采集中存在字段映射错误
4. **报价为空**（图文和视频报价均缺失）**或粉丝量为 0** → 确认 blogger API 是否正常返回，是否存在采集异常

**🟡 软性提醒（根据 campaign 和产品的具体要求来判断，非硬性条件）：**
5. **女性粉丝占比 < 0.5** → 若目标用户为女性则需注意，但非必须修正的数据错误

输出校验报告给用户（🔴 硬性问题 / 🟡 需确认 / ✅ 数据完整），给出修复建议及需人工判断的说明。

## 采集字段清单

CSV 输出包含以下字段。**生成采集脚本时，必须使用「仅自然流量」（`advertiseSwitch=0`）获取日常笔记和合作笔记的 notes_rate 数据，不能使用默认的「全部流量」。时间范围筛选近 30 天。**

| 类别 | 字段 | 数据来源 |
|------|------|---------|
| **基础信息** | 达人名称、内容类目、地域、粉丝量、粉丝所在区域（前五城市）、获赞与收藏 | blogger API |
| **粉丝画像** | 女性粉丝占比 | fans_profile API |
| **报价** | 图文报价（万）、视频报价（万） | blogger API（元→万转换） |
| **日常笔记**（近30天·仅自然流量） | 发布篇数、曝光中位数、阅读中位数、点赞中位数 | notes_rate API **必须传 `advertiseSwitch=0`** |
| **合作笔记**（近30天·仅自然流量） | 发布篇数、曝光中位数、阅读中位数、点赞中位数 | notes_rate API **必须传 `advertiseSwitch=0`** |
| **合作笔记最低曝光**（近30天） | 最低曝光、最低曝光阅读、最低曝光点赞、最低曝光收藏、最低曝光评论、最低曝光时间、最低曝光品牌 | notes_detail API + 抽屉 DOM 提取 |
| **合作笔记最低点赞**（近30天） | 最低点赞、最低点赞阅读、最低点赞收藏、最低点赞评论、最低点赞时间、最低点赞品牌 | notes_detail API + 抽屉 DOM 提取 |
| **预估指标** | 预估CPM、预估CPE | 根据最低曝光/最低点赞计算 |

## 关键原则

1. **CDP 始终使用已打开的 Chrome**
2. **先探索再提问** — 不要跳过 Step 2
3. **搜索 API payload 必须完整** — 不要省略字段
4. **详情页必须关闭** — 每处理完一个 KOL 就关闭
5. **CSV 去重** — 多次运行不重复
6. **脚本可复用** — 为用户加 `--config` 参数支持下次复用
7. **所有产出在工作区文件目录**
8. **平台专注** — 仅小红书蒲公英
