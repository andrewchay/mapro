# 方案分阶段交付（Proposal Phasing）

## 这个 Skill 做什么

把"一次交付几十页、返工全量重写"改成"三阶段递进、每阶段有挂起门"：M0 对齐 → M1 骨架+样例 → M2 全案。同时执行四条交付纪律（编号客户化、声明集中、版本命名、历史不覆盖），让交付物在客户视角可直接阅读与决策。

**为什么存在**：历史项目（此初，2026-09）中 v1→v5 每轮反馈都触发 30+ 页全量重写；内部编号（W03/B08/D7）暴露给客户触发第 13 轮反馈；同名文件覆盖导致历史不可追溯，最后靠人工整理归档档案补救（第 14 轮反馈）。**分阶段交付把返工粒度从"整版"降到"页"；交付纪律把"反馈才修"变成"生成即正确"。**

## 核心规则（最高优先）

**1. 三阶段定义与页数上限（强制）**

| 阶段 | 内容 | 页数上限 | 挂起门 |
|---|---|---|---|
| **M0 对齐** | 五类形态假设（形态/平台/预算/人群/合规）+ 洞察方向 + 建议路线 | 3 页 | 客户确认假设后才可进 M1；由 `ma-brief-intake` 产出 |
| **M1 骨架+样例** | 全案骨架（章节级）+ **每条内容线各 1 个全颗粒度样例**（标题/封面/首屏/正文/末页完整到可直接执行）+ 预算结构 + 上线顺序 | 12 页 | 客户确认样例风格与骨架逻辑后才可进 M2 |
| **M2 全案展开** | 完整内容清单、逐条排期、预算明细、验证与复盘机制 | 不设上限 | M2 反馈只做页级修改，不重写骨架 |

**2. M1 样例必须全颗粒度（强制）**：样例不是"标题+方向"，必须完整到客户能想象发布后的样子；样例被否只重写样例，不动骨架。**禁止跳过 M1 直接交付 M2**——除非客户明确书面要求一次全量。

**3. 编号客户化（强制）**：面向客户阅读的页面正文**禁止出现内部编号**（内容 ID 如 B06/W03、排期代号如 D7/D8-11、内部工具名、skill 名）。编号只保留在执行说明、备注、附录对照表中。页面正文使用客户可直接读懂的中文命名（如"产后自我照顾清单""第 7 天"）。

**4. 免责声明集中（强制）**：研究口径、数据边界、待验证假设等声明**集中在一页"资料使用口径"**，正文中仅在必要时一句话引用；禁止每页备注重复整段声明（防御性声明过密会降低决策可用性）。每页备注保留：依据文件 + 与集中页的差异项。

**5. 版本语义命名与历史不覆盖（强制）**：方案文件名必须含版本语义（如 `方案名_v5.pptx`），禁止用日期替代版本号；新版独立成文件，旧版 HTML/PPTX/布局 JSON/生成脚本**保留不删除**；布局数据与生成器随版本同存，保证可复现。

**6. 一页一决策（强制）**：M1/M2 每页标题即结论，页面内容支撑该结论；纯推导过程页合并或移附录。客户反馈"页数多/看不完"时先做减法（收页）而不是重写。

## 何时使用

**✅ 触发**
- 客户要求产出方案/提案/整合文档，且尚未有确认过的 M0
- 已有 M0/M1，需要进入下一阶段
- 方案返工请求 → 先判断属于哪一阶段的反馈，只在对应阶段内修改

**❌ 不触发**
- 单条内容创作（ma-script-studio 等）
- PPT 排版与视觉制作（guizang-ppt-skill：本 skill 定义"放什么、怎么分阶段"，排版工具负责"怎么做漂亮"）
- 达人稿件审核（ma-draft-review）

## 工作流

### Step 1 · 阶段判定

检查当前已有材料：无确认 M0 → 从 M0 开始；有 M0 → 做 M1；有确认 M1 → 做 M2。返工请求先归位到 M0/M1/M2 某一阶段，禁止跨阶段全量重写。

### Step 2 · 产出该阶段交付物

按阶段定义与页数上限产出；引用 `ma-brief-intake` 的对齐卡作为 M0 基线，引用 `ma-search-bridge` 决策表作为搜索承接章节。

### Step 3 · 交付可读性与决策链检查（交付前逐项过）

- □ 内部执行稿逐项追溯：业务目标 → 决策任务 ID/目标判断 → 主张及证据来源 → 内容与触点 → 行动及承接 → 对应指标；缺环节须列出待确认，不得声称方案已验证。对外页面用可读中文表达，不暴露内部 ID。此项是方案级一致性检查，不改变 `ma-draft-review` 稿件三态的红卡口径。
- □ 页面正文无内部编号/工具名/skill 名
- □ 每页标题即结论；推导过程已收进附录或备注
- □ 免责声明集中一页；各页备注无重复整段声明
- □ 文件名含版本号；旧版本文件仍在；布局 JSON/生成脚本同存
- □ 样例全颗粒度（M1）；31 条级清单与样例数一致（M2），不虚增条目

### Step 4 · 挂起与确认

按挂起门等待客户确认；确认意见记录进对齐卡/阶段验收记录，作为下一阶段输入。客户确认话术模糊时（"差不多/可以"）追问一句具体确认范围，避免带着模糊确认铺量。

## 各阶段产出模板

```
M0（≤3 页）：假设表（五类×置信等级）｜未决问题清单｜建议路线
M1（≤12 页）：骨架目录｜每内容线 1 个全颗粒度样例｜预算结构｜上线顺序｜资料使用口径（集中声明页）
M2（不限）：完整清单（与样例编号一致）｜逐条排期｜预算明细｜验证与复盘机制｜附录（编号对照表/依据文件清单/历史版本索引）
```

## 与其他 Skill 的分工

- **ma-brief-intake**：M0 的产出者；本 skill 消费其结果决定能否进 M1。
- **ma-search-bridge**：搜索承接章节的内容来源；决策表进入 M1/M2 时按编号客户化规则转写。
- **guizang-ppt-skill**：M1/M2 的排版执行工具；本 skill 的页数上限与"一页一决策"约束它的输入。
- **ma-content-calendar**：M2 的排期来源；排期须与 M1 确认的上线顺序一致。
- **ma-draft-review**：稿件级审核；方案级可读性检查由本 skill Step 3 负责。
