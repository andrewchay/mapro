# 项目启动对齐门（Brief Intake）

## 这个 Skill 做什么

在任何策略、创意、内容开发开始之前，把"客户脑子里的方案形态"和"工作流默认产出的方案形态"对齐。产出一份 1-3 页的 **M0 对齐卡**：五类关键假设逐项标注[已确认/待确认/工作假设]，并列出未决问题清单。

**为什么存在**：历史项目（此初，2026-09）中，"客户要轻量社媒内容、工作流默认产出 TVC/剧情片全案"这一形态错位直到第 9 轮反馈才被纠正，导致 v1 整版、视觉方案、TVC 资产全部作废；"产品是普通食品"这一合规边界在第 5 轮反馈才被厘清。**五类假设中任何一个错了，下游所有产出都要重写**——所以它们必须在第 0 步确认，而不是在反馈中收敛。

## 核心规则（最高优先）

**1. 五类假设逐项过，一项都不能跳（强制）**

| # | 假设 | 要确认什么 | 无信号时 |
|---|------|-----------|---------|
| 1 | **交付形态** | 轻内容（社媒图文/短视频/直播）/ 重制作（TVC/剧情片/平面大片）/ 两者组合及比例；是否需要分镜级脚本 | **必须问**，不得从 brief 行数多少推断 |
| 2 | **平台主次** | 主阵地（先集中做通的平台）+ 延展平台（首月是否必发）；是否含线下 | 有明确投放平台记录则标注[已确认]，否则问 |
| 3 | **预算量级与结构** | 总盘；达人池/制作/测试/运营的拆分；达人层级配比偏好 | **必须问**。无预算信息时禁止按"典型配比"假设并展开报价级方案 |
| 4 | **人群颗粒度** | 核心 TA 是谁（阶段限定，如"初育妈妈"而非"妈妈/女性"）；有无排除人群 | 从 brief 提取并复述给客户确认；禁止默认泛化 |
| 5 | **品类合规类别** | 普通食品 / 保健食品 / 药品 / 化妆品 / 服务等；由此确定功效表达边界 | 从产品资质材料确认；**拿不到资质就必须按最严格口径（普通食品）并显式声明** |

**2. 每项假设必须带置信标注（强制）**：[已确认]（客户原话或书面材料）/ [待确认]（已列入未决问题）/ [工作假设]（基于行业惯例推断）。[工作假设] 只能用于方案框架，**禁止据此展开重制作资产（TVC 分镜/剧情脚本/视觉全案）或报价级预算方案**。

**3. 未确认不进入下游（强制）**：五类假设中交付形态、预算结构、品类合规三项存在[工作假设]时，M0 对齐卡交付后**挂起**，等客户确认后再调用下游 skill（ma-ta-portrait、ma-consumer-insight、ma-creative-concept 等）。客户明确说"先做着看"时，可继续研究类工作，但重制作资产仍锁死。

**4. 信号优先级（强制）**：客户原话 > 书面 brief > 历史合作记录 > 行业惯例。上一轮项目学到的默认值**不得**直接套用到新项目，只能作为[工作假设]的依据来源并注明。

**5. 历史洞察不复活（强制）**：若客户提供过往方案或历史文档，其中已被撤回的洞察、旧视觉方向、旧内容模型**不得**默认沿用；须按当前 brief 重新判定并在对齐卡中标注"历史资产沿用/弃用"。

**6. brief 违规表述转译（强制）**：客户 brief/会议纪要中常出现超出品类边界的功效宣称（如普通食品被表述为"对应乳腺炎缓解""舒缓情绪压力"）。对齐卡必须逐条转译：原文标注「品牌声称·资质未核验·不用于对外表达」，并给出中性需求描述；**禁止把 brief 原文功效表述直接复用为下游（画像/洞察/创意/内容）输入**——下游 skill 引用的只能是转译后的口径。这不是否定客户材料，而是把合规边界在第 0 步讲清，避免下游返工。

## 何时使用

**✅ 触发**
- 新项目/新 campaign 启动：立项、开始做方案、接需求、发来 brief（文本/PDF/会议纪要）
- 已有项目出现方向级转向（换人群、换平台、换产品线）→ 重新过一遍对齐门
- 客户反馈中出现"方向不对 / 不是我想要的 / 重做" → 先回 M0 核对假设，再返工

**❌ 不触发**
- 已有确认过的 M0 对齐卡的常规迭代（直接进下游）
- 单条内容创作、达人稿件审核（各自有专门 skill）
- 纯数据回收、复盘类任务

## 工作流

### Step 1 · 信息收集

收集：品牌/产品资料、brief 原文、会议纪要、历史合作文档、产品资质（标签/许可证/检测报告）。缺资质材料时在未决问题清单中置顶。

### Step 2 · 信号提取

从材料中逐项提取五类假设的现有信号，区分"客户明确说的"与"自己推断的"。

### Step 3 · 假设卡片

每个假设输出四要素：
- **当前理解**：一句话结论
- **依据**：客户原话/材料出处，或推断理由
- **若错了会怎样**：下游哪些产出需要重写（量化到 skill 环节）
- **待确认问题**：给客户的具体问题（客户只需简短回答）

### Step 4 · 输出 M0 对齐卡并挂起

- 对齐卡 1-3 页：五类假设表 + 未决问题清单 + 建议的下一步
- 交付方式：轻量文档/消息均可，不要求 PPT
- 挂起规则见核心规则 3；客户全部确认后，对齐卡即成为下游所有 skill 的输入基线

```
|---|---|---|---|---|
| 交付形态 | … | [已确认/待确认/工作假设] | … | … |
| 平台主次 | … | … | … | … |
| 预算结构 | … | … | … | … |
| 人群颗粒度 | … | … | … | … |
| 品类合规 | … | … | … | … |

## 表述转译（若 brief/纪要含超品类边界的功效宣称）

|---|---|
| …（原文摘录） | 「品牌声称·资质未核验·不用于对外表达」＋中性需求描述（如"希望减少哺乳期身体不适的反复"） |

```

## 与其他 Skill 的分工

- **ma-marketing（StrategyIQ）**：生成完整策略提案；本 skill 是它的前置门——五类假设确认后，StrategyIQ 的产出才有稳定基线。
- **ma-ta-portrait / ma-consumer-insight / ma-creative-concept**：下游消费对齐卡；对齐卡中的[工作假设]会被这些 skill 继承标注，禁止静默转为"已确认"。
- **ma-proposal-phasing**：M0 对齐卡即分阶段交付的 M0 交付物；两者配合使用。
- **ma-draft-review**：管稿件审核；不管项目对齐。
