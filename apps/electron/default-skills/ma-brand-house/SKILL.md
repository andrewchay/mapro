# 品牌屋（Brand House）结构化生成

## 这个 Skill 做什么

基于品牌 DNA 和定位，生成结构化的品牌屋架构，确保品牌各层级逻辑自洽：
- **顶层**：品牌愿景 / 品牌使命
- **上层**：品牌价值观 / 品牌个性
- **中层**：品牌核心利益点（功能利益 + 情感利益）
- **下层**：支持点 / 证据（RTB - Reasons to Believe）
- **基础**：目标人群 / 使用场景

## 何时使用

**合适的场景：**
- 新品牌从 0 到 1 的品牌架构搭建
- 品牌焕新后的品牌屋重构
- 品牌定位梳理和内部对齐
- 比稿/提案中的品牌策略部分
- 品牌 DNA 已有但需要结构化呈现时

**不合适的场景：**
- 没有品牌 DNA 基础时（建议先使用 ma-brand-dna）
- 纯战术层面的单次 campaign 创意
- 已有成熟品牌屋仅需微调时
- 没有明确 TA 画像时（建议先使用 ma-ta-portrait）

## 工作流

### Step 1 · 输入确认

确认以下信息是否充足：
| 信息项 | 说明 |
|--------|------|
| 品牌 DNA | 核心价值、品牌人格、调性 |
| TA 画像 | 目标人群特征、痛点、欲望 |
| 竞品定位 | 主要竞品的品牌定位（用于差异化） |
| 产品/服务 | 核心产品功能、差异化优势 |

### Step 2 · 品牌屋构建

逐层构建品牌屋：
- **顶层**：品牌愿景（长远理想）/ 品牌使命（存在的意义）
- **上层**：品牌价值观（信仰）/ 品牌个性（拟人化特质）
- **中层**：核心利益点 — 功能利益（产品解决什么问题）+ 情感利益（用户感受到什么）
- **下层**：RTB 支持点（为什么用户要相信）
- **基础**：目标人群（对谁而言）/ 使用场景（在什么情况下）

### Step 3 · 一致性检查与输出

检查各层级之间的逻辑自洽性：
- 上层是否能被下层支撑？
- 核心利益点是否有 RTB 支持？
- 定位宣言是否完整覆盖所有层级？
- 生成候选 slogan/tagline

## 输出格式

必须以 JSON 格式返回：

```json
{
  "brand_house": {
    "vision": "品牌愿景 — 品牌希望实现的长期理想状态",
    "mission": "品牌使命 — 品牌为什么存在，要解决什么问题",
    "values": [
      "价值观1：如'真诚'",
      "价值观2：如'创新'",
      "价值观3：如'用户至上'"
    ],
    "personality": [
      "个性特质1：如'年轻活力的'",
      "个性特质2：如'专业可信的'",
      "个性特质3：如'敢于打破常规的'"
    ],
    "core_benefit": {
      "functional": "功能利益 — 产品具体解决什么问题，提供什么实用价值",

      "支持点3：品牌背书或权威认证"
    ],
    "target": {
      "audience": "目标人群 — 核心用户画像描述",
      "occasion": "使用场景 — 用户在什么情况下需要这个品牌"
```

## 规则

1. **品牌屋各层级必须逻辑自洽**：上层必须能被下层支撑，如"情感利益"必须能被"品牌价值观"解释，"功能利益"必须能被"RTB"证明
2. **核心利益点要区分功能利益和情感利益**：功能利益回答"有什么用"，情感利益回答"感觉如何"，两者缺一不可
3. **RTB（支持点）要具体可信**：必须是可验证的事实（如"含 99% 高纯度烟酰胺"），不是空洞承诺（如"最好的品质"）
4. **定位宣言必须遵循标准格式**："对[目标人群]而言，[品牌]是[品类]中唯一能[核心利益]的选择，因为[RTB]"
5. **品牌个性要拟人化**：用"像什么样的人"来描述（如"像一位懂你的朋友"），不是抽象形容词堆砌
6. **愿景和使命要区分**：愿景是"未来想成为什么"（方向），使命是"现在每天做什么"（行动），不混用
7. **slogan 候选要差异化**：至少 3 个不同方向的候选（如理性诉求/情感诉求/态度表达），不全是同一风格的微调
