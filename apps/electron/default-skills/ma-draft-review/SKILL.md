# 达人稿件三态审核

## 这个 Skill 做什么

代替"不常在线"的我方关键人，自动审核第三方在群里提交的达人稿件并回复。第三方收达人稿件 → 群里提交 → 读取稿件 → 结合 brief 审核 → 三态回复，第三方据此转达人修改。

- 🔴 **block（严重）**：@第三方 + 逐条修改意见（合规一票否决 / 大幅修改）
- 🟡 **minor（一般）**：附修改建议 + @我方关键人跟进
- ✅ **pass（通过）**：简短确认可发布

同时管理达人 brief（导入/查询/更新），供审核时按达人名匹配对照。

## 何时使用

**✅ 触发（群消息中出现以下任意特征）**
- 提交待审核交付物：初稿 / 改稿 / 终稿 / 成片 / 发布预览 / 请查收 / 请审核 / 辛苦审核 / 审核一下 / 稿件 / 审一下（且消息含 附件/链接/内容锚点，如"稿/片/版/预览/内容/文案"）
- 独立长文案（>=80 字，无链接，含"文案/标题/话题/正文/#"标记）也可视为达人文案审核
- brief 管理："录入brief / 导入brief / 达人brief"

**❌ 不触发**
- 纯闲聊、非文本消息
- 数据汇报 / 发布通知 → 用 `ma-publish-data-track`
- 风险预警（延期/拒付/失联等）→ 直接人工研判，本 skill 不做

## 审核流程

```
稿件(文档链接/文件/消息文案) → 提取文字+图片 → 按达人名匹配 brief
  → 文字审核(三维) + 图片审核(Kimi) → 合并 → 三态回复（标注第 N 版）
```

### Step 1 · 提取达人名

按优先级从消息中提取：
1. `【XX】` 括号包裹的达人名（如"【忘记加芋泥】初稿已过"）
2. 消息任意位置紧邻稿件关键词的 2-12 字 token（如"梦梦呀的预览看看" → 梦梦呀）
3. 文件提交时从文件名兜底（去扩展名 + 去"初稿/改稿/预览"等后缀）
4. 提取失败 → 达人名为空，审核时用通用框架

### Step 2 · 读取稿件内容

按优先级尝试，失败自动降级下一档：
1. **飞书文档/wiki 链接**：用 WebBridge 或飞书文档 API 读取正文 + 提取图片块
2. **文件**（docx/txt/md）：解析正文 + 提取 docx 内联图片
3. **消息内文案**：直接用消息文本
4. 全部失败或内容过短（<30 字）→ **转人工**：群内提示"稿件无法自动审核：{原因}，已转人工审核"，不自动催办

### Step 3 · 匹配 Brief

- 按达人名查找 `workspace-files/briefs/{达人名}.md`
- 找到 → 审核 prompt 带入 brief 对照品牌要求
- 未找到 → 按通用投放要求审核，回复注明"未录入 brief，按通用投放要求审核"

### Step 4 · 文字审核（三维 + 投放执行要点）

调用 LLM（复用 ma-content-audit 三维方法论 + 投放执行要点），输出：

| 维度 | 要点 |
|------|------|
| 合规性 | 敏感词、平台规范、广告法合规（**一票否决**） |
| 品牌契合度 | 结合 brief：内容方向、文案卖点、品牌调性 |
| 内容质量 | 结构、逻辑、可读性 |
| 投放执行要点 | 话题 tag 是否落实、发布预览规范 |

### Step 5 · 图片审核（Kimi 视觉）

- 稿件含图片时，调用 Kimi 视觉模型审核：场景氛围 / 产品特写 / 构图重复 / 摆拍痕迹 / 品牌露出 + 画面质量 / 品牌契合 / 合规
- 用 `KIMI_API_KEY` + OpenAI 兼容协议调 `moonshot-v1-8k-vision-preview`
- 图片审核结果与文字合并：**verdict 取较严重者**，图片问题前置到修改意见，回复显示"文字 X/图片 Y"双分
- 未配置 `KIMI_API_KEY` 或调用失败 → 仅用文字审核，回复注明"稿件含 N 张图片未审"
- 降级：未配置 Kimi 时可用 MAPro 渠道多模态模型替代

### Step 6 · 三态判定与回复

```
verdict 规则：
  block  = 合规一票否决 或 总分 < 70
  minor  = 70 <= 总分 < 90
  pass   = 总分 >= 90
```

| 判定 | 回复内容 | @目标 |
|------|---------|-------|
| 🔴 block | 📦 第 N 版稿件修改意见：达人名 + 总分 + 三维分 + ⚠️合规一票否决 + 逐条修改意见（最多 5 条，图片问题前置）+ 总体建议 | @第三方提交人 |
| 🟡 minor | 📦 第 N 版稿件修改意见：达人名 + 总分 + 三维分 + 修改建议（最多 5 条）+ 总体建议 | @我方关键人跟进 |
| ✅ pass | "第 N 版 稿件初审通过（总分 X/100），可进入发布预览。" | 无 |

**版本标注**：按 (群, 达人) 累计，同达人改稿递增，不同达人独立。回复前缀标注"📦 第 N 版"。

## 角色识别（第三方 vs 我方关键人）

群成员名称前缀是区分角色的**唯一权威口径**（不看职位、不看性格、不做语义推测）：

| 角色 | 群成员名称前缀 | 回复时 @ 谁 |
|------|--------------|------------|
| 我方关键人 | `营销-姓名`（如「营销-小明」） | 需要我方跟进时 @ 前缀含 `营销-` 的成员 |
| 第三方 | `执行-姓名`（如「执行-阿强」） | 稿件待改时 @ 提交人/相关 `执行-` 成员 |

识别方法（在 Step 6 回复前执行）：
1. 从群聊上下文/群成员列表中取出所有成员名称
2. 按前缀归类：`营销-*` → 我方关键人；`执行-*` → 第三方
3. 无前缀或前缀不明确的成员 → 保守视为第三方，不当作我方关键人
4. 我方可能有多个、第三方可能有多个，均可按前缀列出全部，选择与当前稿件相关的人 @
5. @ 时直接用 `@姓名` 格式（bridge 会自动转换为飞书 `<at>` 精准提醒对应成员）

> 校验口径固定为「营销-」表示我方关键人、「执行-」表示第三方。若后续角色/前缀调整，只改本规则，不改回复逻辑。

## Brief 管理

存储约定：`workspace-files/briefs/{达人名}.md`

| 操作 | 触发词 | 动作 |
|------|--------|------|
| 导入 | 录入brief / 导入brief + 文档链接 + 达人名 | 读文档 → 提取达人名+核心要点 → 写入 `workspace-files/briefs/{达人名}.md` |
| 查询 | 达人brief / brief是什么 | 列出该达人 brief 或确认是否存在 |
| 更新 | 更新brief + 文档链接 | 覆盖写入同名文件 |

brief 文档来源支持：飞书文档/wiki 链接、本地文件、PDF（提取全文，按达人名匹配分 brief 页）。

## 转人工兜底

以下情况自动转人工（提示第三方，不自动催办）：
- 稿件读取失败 / 无法解析文件内容
- 内容过短（<30 字）
- LLM 未配置或审核调用失败

群内提示："稿件无法自动审核：{原因}，已转人工审核。"

## 关键配置

| 配置 | 说明 |
|------|------|
| `KIMI_API_KEY` | Kimi 视觉 key（未配则图片审核关闭，降级文字审核或 MAPro 渠道多模态） |
| `KIMI_BASE_URL` / `KIMI_MODEL` | 默认 `https://api.moonshot.cn/v1` / `moonshot-v1-8k-vision-preview` |
| `REVIEW_PASS_SCORE` / `REVIEW_MINOR_SCORE` | 分档阈值，默认 90 / 70 |
| `BRIEF_AUTO_MATCH` | 按达人名自动匹配 brief，默认开启 |
| 审核用 LLM | 复用 MAPro 已配置渠道（DeepSeek/OpenAI 兼容等） |

## 状态存储

- `workspace-files/briefs/{达人名}.md` — brief 文档
- `workspace-files/draft-review-state.jsonl` — 版本计数（按 群+达人，JSONL 追加）

## 与相关 Skill 的边界

- `ma-content-audit`：提供三维审核方法论，本 skill 在其基础上增加 brief 对照、图片审核、三态分档、版本标注、投放执行要点
- `ma-publish-data-track`：负责发布后数据（发布记录/报数/异常预警），本 skill 只管审稿
